# 怎么演示这个项目

这份说明给两种场景用：

- 发 GitHub：让别人快速看懂这个项目做了什么。
- 面试演示：按步骤打开页面，证明 RAG 和 Agent 不是写死的。

## 一句话介绍

这是一个企业 AI Agent 工作台。它能把企业资料导入知识库，解析成文本，切成 chunk，写入本地检索库；用户提问后，系统会先做 RAG 检索，再调用模型生成回答，并把每一步执行过程展示在 Trace 里。

可以这样说：

> 这个项目不是普通聊天框。普通聊天框只负责问答；这个工作台多了知识库入库、RAG 检索、工具调用、执行 Trace 和安全校验。面试时我可以现场导入一份资料，再让 Agent 根据这份资料回答问题。

## 现场怎么用

启动后端：

```bash
python3 -m uvicorn backend.app.main:app --port 8010
```

启动前端：

```bash
VITE_API_BASE_URL=http://127.0.0.1:8010/api npm run dev:web -- --host 127.0.0.1 --port 5176 --strictPort
```

打开页面：

```text
http://127.0.0.1:5176/
```

页面操作顺序：

1. 右侧“知识库”导入一份资料。推荐用“路径导入”，最稳定。
2. 左侧选择“企业知识库 Agent”。
3. 中间输入一个和资料相关的问题。
4. 点击“一键跑通 / 一键验证”。
5. 看“一键跑通”的三步状态：检查知识库、诊断 RAG、运行 Agent。
6. 看“RAG 命中”：证明问题命中了哪几段知识。
7. 看“Agent 回答预览”：证明模型根据资料生成了回答。
8. 看右侧“执行 Trace”：证明系统不是固定文案，而是有执行链路。

## 演示 RAG 时怎么讲

RAG 的重点不是“模型会回答”，而是“模型回答前有没有查到资料”。

演示时按这个顺序说：

1. 先导入一份知识文件。
2. 告诉对方：系统会保存原文件和解析文本。
3. 再告诉对方：后端会把文本切成 chunk，写入 SQLite 检索库。
4. 输入一个文件里能找到依据的问题。
5. 点“一键验证”。
6. 指给对方看“RAG 命中”区域。

可以这样讲：

> 这里不是直接把问题扔给大模型。系统先从知识库里找相关 chunk，再把这些 chunk 作为上下文交给模型。你看这里的 RAG 命中，能看到它命中了哪份文档、哪几个片段和分数。这样回答就有来源，不是模型凭空编。

推荐演示问题：

```text
客户提交普通工单后多久首次响应？请引用知识库依据。
```

如果命中了资料，就重点看：

- 命中文档名
- chunk 分数
- 回答里有没有引用来源
- 回答是否贴合导入的资料

## 演示 Agent 时怎么讲

Agent 的重点不是“多轮聊天”，而是“它会按步骤完成任务”。

这个项目里的 Agent 做了几件事：

1. 理解用户问题。
2. 判断当前属于哪个业务场景。
3. 做 RAG 检索。
4. 调用模拟业务工具，比如 CRM、ERP、WMS。
5. 做安全校验，高风险动作只生成建议，不直接改系统。
6. 生成最终回答。
7. 把全过程写进 Trace。

可以这样讲：

> 我这里把 Agent 的执行过程拆开了。它不是黑盒回答，而是每一步都可观察。右侧 Trace 里能看到任务拆解、RAG 检索、工具调用、安全校验和最终结论。面试官如果问它到底做了什么，我可以直接看 Trace。

演示时重点指三个地方：

- “一键跑通”：证明流程能完整跑完。
- “Agent 输出”：看最终业务结论。
- “执行 Trace”：看每一步怎么来的。

## 三个可演示场景

### 1. 企业知识库 Agent

适合演示 RAG。

可以问：

```text
客户提交普通工单后多久首次响应？请引用知识库依据。
```

你要强调：

- 文档能入库。
- 问题能命中文档。
- 回答能引用来源。

### 2. 外贸销售 Agent

适合演示“业务场景 + 工具调用”。

可以问：

```text
帮我判断海外渠道商是否能申请账期，并说明需要哪些审批材料。
```

你要强调：

- Agent 会结合客户、渠道、账期等业务规则。
- 不是只做文本问答，还会进入业务判断。

### 3. 供应链 Agent

适合演示“企业系统集成”。

可以问：

```text
检查当前库存是否有缺货风险，并给出采购建议。
```

你要强调：

- Agent 可以调用模拟 ERP / WMS 数据。
- 高风险动作不会直接执行，只生成审批建议。

## 面试官可能会问什么

问：这是不是真 RAG？

答：

> 是。文件上传后会被解析、切 chunk，并写入 SQLite。提问时先走检索，再把命中的 chunk 发给模型。页面上的 RAG 命中可以看到召回结果。

问：这是不是写死的 Demo？

答：

> 不是。你可以现场换一份文件、换一个问题。只要资料里有依据，RAG 命中和回答都会变化。

问：Agent 体现在哪里？

答：

> Agent 不只是聊天，而是执行链路。这里有任务拆解、RAG 检索、工具调用、安全校验和 Trace 留存。

问：后续怎么升级？

答：

> 当前用 SQLite 和本地哈希向量做轻量版本。后续可以换成 pgvector 或 Qdrant；Agent 编排可以换成 LangGraph；企业工具可以用 MCP 接入真实 CRM、ERP、WMS。

## 最短演示话术

如果只有 2 分钟，就这么讲：

> 我先导入一份企业资料。导入后，系统会保存原文件、解析文本，并切成 chunk 写入检索库。现在我问一个资料里的问题，点击一键验证。这里能看到它先检查知识库，再做 RAG 检索，最后运行 Agent。RAG 命中区域能看到召回了哪些文档片段，Agent 回答区域能看到最终结论，右侧 Trace 能看到任务拆解、检索、工具调用和安全校验。这个项目的重点不是做一个聊天框，而是把企业 Agent 的执行过程做成可观察、可解释、可演示的闭环。
